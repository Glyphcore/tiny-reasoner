# Findings: computed weight edits on Qwen3-0.6B (CPU, no training)

Model `Qwen/Qwen3-0.6B` revision `c1899de289a04d12100db370d81485cdf75e47ca`, apache-2.0. CPU, fp32, 4 threads, greedy decoding
(this container has no GPU; the GTX 1660 Ti fp16 path is untested). Held-out split: 18 game episodes, 120 legality-judge probes,
5 multi-turn chats, perplexity on a fixed text set. Table and run ids: `docs/handoff.md` (generated by `tools/table.py` from
`runs/*/summary.txt`); side-by-side chats: `docs/chats_base_vs_edit.md`. Every edit reverted to the base hashes exactly
(`revert_exact` yes in every run).

## Noise first
Judge accuracy has a standard error of about 0.045 and the game solve rate about 0.09 on these sizes. A difference smaller than
two of those is not a result. Only one edit moved anything outside that band.

## What the inspection found
- The base model answers "legal" to 89% of judge probes (cells: says-legal/is-legal 53, says-legal/is-illegal 52, says-illegal/is-legal 10,
  says-illegal/is-illegal 5), so its judge accuracy of 0.48 is a response bias, not ignorance.
- Re-thresholding its own logit gap lifts dev accuracy from 0.57 to 0.64 with no weight change. Closed-form ridge probes for true
  legality reach 0.74 at the answer position and 0.81 at the proposed-move token. The activations know more than the output says,
  but only partly: the read-out is far from perfect even where the probe is best.

## Edits, in one line each (held-out)
- **Prompt-only hint:** judge unchanged (0.47), games worse (solve 0.00, legal 0.32 against 0.17 and 0.54). The hint hurts play.
- **a1 debias bias (unembed difference baked as a bias):** nothing measurable (judge 0.49, ppl 30.78).
- **a2 steering bias, layer 20:** judge 0.53 only because it answers "legal" every time (63/57/0/0); games worse. Larger scales flip every answer to "illegal".
- **b orthogonalise a self-report direction, layer 12:** judge 0.50, games legal rate up to 0.65 (solve 0.11, inside noise), perplexity 35.55 (worse).
- **c ablate 4 heads (most negative truth-signed attribution):** legal rate 0.68, solve 0.11, judge 0.49, ppl 32.89. Inside noise except perplexity.
- **d calibrated rank-one LoRA-form delta on layer 19 `mlp.down_proj`:** the only edit that moves judging. Cells 35/17/28/40: legal recall falls from
  0.84 to 0.56 while illegal recall rises from 0.09 to 0.70 (balanced accuracy 0.47 to 0.63, arithmetic from the reported cells). It is
  not only a bias flip, since a pure flip would sit near 0.50 balanced, but it is far from the probe's ceiling. It costs game play (solve 0.00,
  legal 0.31) and leaks the word "illegal" into one chat reply, so it is a failure on games and on conversation, a partial success on judging.
- **e task vector, -0.25 of (instruct minus base):** perplexity 24.64 (better), chats 4/5, judge 0.51, solve 0.00. The extra chat pass is a style
  and length change (the base's `arith` failure is a 32-token cutoff), not new competence.

## What failed
- The uncalibrated rank-one route reached 0.64 to 0.67 dev judge accuracy but perplexity exploded (8e5 up to 1e20); the calibration (weighted ridge, silent on
  generic positions) exists because of that.
- Steering, orthogonalisation and head ablation did nothing measurable or hurt.
- The `pushback` chat fails for every variant: the model agrees a tomato is a mineral. No edit touched sycophancy.
- LoRA merge versus unmerge agrees to 3e-5 in logits, but arithmetic unmerge is not bit exact (6e-8), so reverts restore from a backup of the
  original tensors, which is exact.

## Not run
GPU and fp16, thinking mode, larger seed sets, chess, per-edit chat sweeps over scale. With 18 episodes no game result here is firm.

## Reading
At this scale a computed edit can shift what the model says about its own legality judgements when it is built from what its activations
already encode, and it pays for that elsewhere. Direction edits chosen without a verifier-weighted calibration did not help. Nothing here shows
better step-by-step reasoning on the games.
